# Onboarding 与长期记忆能力 Memo v1

> 日期：2026-04-24  
> 状态：已确认方向，待实现  
> 范围：冷启动引导 + lessons 持久化 + Agent 读取

---

## 1. 背景

当前 OpenLoom 已完成元数据提取主链路（Phase 2 后段），开始进入 UI 与交互能力建设。  
在此阶段，发现一个关键缺口：缺少冷启动引导与用户偏好长期记忆能力。

---

## 2. 现状确认（As-Is）

已确认当前系统中：

- 没有专门的冷启动引导页（如“怎么称呼用户/用户怎么称呼 OpenLoom”）。
- 没有落地的 `lessons.md` 读写链路（仅在文档中出现，未形成产品能力）。
- Gateway 仅有基础消息处理（`scan.start`、占位 `chat.message`），缺少 onboarding/memory 接口。
- Agent 侧尚未接入用户偏好记忆（未注入提示词上下文）。

结论：**“引导 -> 记忆 -> AI 使用”闭环目前未实现。**

---

## 3. 决策（To-Be）

先采用 **交互式（interactive）方式** 落地核心功能，暂不做复杂自动化编排。

优先级：

1. 冷启动交互采集用户偏好
2. 持久化为长期记忆文件（`lessons.md`）
3. 在 Agent 运行时读取并注入上下文

---

## 4. 交互式 MVP（核心功能定义）

### 4.1 首次启动引导

首次进入 UI 时，弹出引导流程，至少采集以下字段：

- `user_display_name`：如何称呼用户
- `assistant_display_name`：用户如何称呼 OpenLoom
- `language_preference`：交互语言偏好（默认中文）
- `tone_preference`：语气偏好（简洁/详细）

### 4.2 持久化策略

将引导结果写入：

- `docs/lessons.md`（当前阶段先放 docs 便于观察与调试）

建议记录结构（MVP）：

- 元信息（创建时间、更新时间、版本）
- 用户偏好字段
- 可追加修正记录（后续迭代）

### 4.3 Agent 使用

每次关键 Agent 会话前：

1. 读取 `docs/lessons.md`
2. 提取用户偏好
3. 注入到系统提示或运行上下文中

目标：让 OpenLoom 的输出称呼和语气稳定一致。

---

## 5. 非目标（本阶段不做）

- 多用户账户体系
- 复杂权限与加密存储
- 细粒度记忆冲突合并策略
- UI 的完整设置中心

---

## 6. 下一步执行建议

按“最小可用”顺序实现：

1. Onboarding 页面（交互采集）
2. Gateway 接口（保存/读取 lessons）
3. lessons 文件落盘（`docs/lessons.md`）
4. Agent 上下文注入（称呼 + 语气）
5. 手工回归验证（首次启动、再次启动、偏好更新生效）

---

## 7. 验收标准

- 首次启动必定触发引导，完成后可进入主界面。
- `docs/lessons.md` 成功生成且字段完整。
- 第二次启动不再重复引导（除非手动重置）。
- Agent 输出中正确使用用户定义称呼与语气偏好。
