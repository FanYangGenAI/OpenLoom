## 1. 目标与范围

### 1.1 目标

针对用户本地文件夹中的**单一文档**，进行全面的元数据提取，将非结构化的数字文件转化为结构化的"知识词条"。这是整个 OpenLoom 知识管理体系的**第一道加工环节**，其质量决定了后续 Agent（Identity / Timeline / Narrative）能否生成有价值的洞察。

### 1.2 v1 范围（有意收窄）

**v1 支持的文件类型：**

| 类别 | 具体格式 |
|------|---------|
| 文本文档 | `.txt`, `.md`, `.markdown` |
| Office 文档 | `.docx`, `.doc` |
| 图片 | `.jpg`, `.jpeg`, `.png`, `.heic`, `.webp` |

**v1 明确不支持（后续版本扩展）：**
- PDF（v2）、视频/音频（v3）、压缩包/代码文件（v3+）

## 2. 整体架构：以 Agent 为中心

v1.2 的核心变化：**每种文件类型的处理能力被封装为一个独立 Agent**，Agent 通过调用 Skills 完成具体工作。这样的设计使得：

- 新增文件类型只需新增一个 Agent，不改动已有逻辑
- Agent 的 prompt/指令可独立迭代，不耦合工具代码
- Skills 可跨 Agent 复用（如 `web-search` 同时被两个 Agent 使用）

### 2.1 架构总览

```

### 2.2 TextDocAgent

**职责**：处理文本文档（.txt / .md / .docx），提取完整元数据。

**配置文件**：`src/agents/configs/text-doc-agent.md`

**能力与工具**：

| 工具/Skill | 用途 |
|-----------|------|
| `text-reader`（内置工具） | 读取文件内容（.txt/.md 直读；.docx 用 mammoth） |
| `file-attrs`（内置工具） | 提取 OS metadata + SHA-256 哈希 |
| Gemini 2.5 Pro（LLM） | 语义提取（摘要、标签、时空关系），Structured Output |
| `web-search` Skill | 对不确定的实体名称（人名、地名、机构名）进行网络验证和补全 |

**处理流程**：

```
1. file-attrs → 基础属性 + hash-skip 判断（内容未变则跳过深度提取；若磁盘路径与缓存不一致则仅刷新路径字段并写入 `path_history`，见下文「路径变更」）
2. text-reader → 原始文本 + 文档属性（author）
3. Gemini 2.5 Pro（Structured Output）→ summary / tags / spatiotemporal
4. web-search（按需）→ 对置信度 < 0.7 的实体名称进行网络验证
5. 持久化 → .openloom/metadata/text_docs/{hash}.md
```

### 2.3 ImageAgent

**职责**：处理图片文件（.jpg / .png / .heic / .webp），提取完整元数据含人脸。

**配置文件**：`src/agents/configs/image-agent.md`

**能力与工具**：

| 工具/Skill | 用途 |
|-----------|------|
| `file-attrs`（内置工具） | 提取 OS metadata + SHA-256 哈希 |
| `exif-reader` Skill | 提取 GPS、拍摄时间、设备信息 |
| `ocr` Skill | 提取图片内文字（DeepSeek，在线/本地可切换） |
| `face-detector`（内置工具） | 人脸检测 + 截图裁剪 |
| Gemini 2.5 Pro Vision（LLM） | 多模态理解（场景/人物/地点描述），Structured Output |
| `web-search` Skill | 对推断的地名、机构名进行网络验证 |

**处理流程**：

```
1. file-attrs → 基础属性 + hash-skip 判断（内容未变则跳过深度提取；若磁盘路径与缓存不一致则仅刷新路径字段并写入 `path_history`，见下文「路径变更」）
2. exif-reader → GPS / 时间 / 设备（有 GPS → 反地理编码 → place_name）
3. ocr（图片含文字时触发）→ 文字内容
4. Gemini 2.5 Pro Vision（Structured Output）→ summary / tags / spatiotemporal / location_inferred
5. web-search（按需）→ 验证推断的地名、机构名
6. face-detector → faces[] + 保存截图至 .openloom/faces/
7. 持久化 → .openloom/metadata/images/{hash}.md
```

### 3.2 web-search Skill

**功能**：通过 Google Custom Search API 对未知实体（人名、地名、机构名、专有词汇）进行网络搜索，返回简短的核实信息，用于补全和验证元数据中的命名实体。

**触发场景**：
- 从文档中提取到不确定的人名（如缩写、别称）
- 从图片中推断出可能的地名但置信度不足
- 出现从未见过的机构名、品牌名

**SKILL.md**：

```markdown
---
name: web-search
description: "Search the web using Google Custom Search to verify and enrich entity names (persons, places, organizations, and terms) found during metadata extraction. Use this when an extracted entity name is uncertain, ambiguous, or needs additional context."
metadata: { "openclaw": { "emoji": "🔍", "requires": { "env": ["GOOGLE_SEARCH_API_KEY", "GOOGLE_SEARCH_CX"] } } }
allowed-tools: ["WebFetch"]
user-invocable: false
---

# Google Web Search Skill

This skill performs targeted web searches to verify and enrich entity information extracted during metadata analysis.

## When to use

- An extracted person name is ambiguous or incomplete (e.g., "小李", "J. Zhang")
- A place name inferred from image content needs verification
- An organization name is unfamiliar or could refer to multiple entities
- A technical term or proper noun needs a brief definition for context

## Usage

Run the search script with a query:

```bash
node {baseDir}/scripts/search.js "<query>" [--num=3]
```

## Output format

Returns JSON:
```json
{
  "query": "original search query",
  "results": [
    {
      "title": "Result title",
      "snippet": "Brief description",
      "url": "https://..."
    }
  ]
}
```

## Important notes

- Use concise, targeted queries (e.g., "迪士尼乐园 上海 地址" not "帮我找关于迪士尼的信息")
- Limit to 1–3 results; this is for quick entity verification, not deep research
- If results are inconclusive, keep the original extracted value with a lower confidence score
```

**search.js 实现逻辑**：

```javascript
// skills/web-search/scripts/search.js
// 调用 Google Custom Search JSON API
// 参数：<query> [--num=N]
// 环境变量：GOOGLE_SEARCH_API_KEY, GOOGLE_SEARCH_CX
// 输出：JSON to stdout

const query = process.argv[2];
const num = parseInt(process.argv.find(a => a.startsWith('--num='))?.split('=')[1] ?? '3');

const url = `https://www.googleapis.com/customsearch/v1?key=${process.env.GOOGLE_SEARCH_API_KEY}&cx=${process.env.GOOGLE_SEARCH_CX}&q=${encodeURIComponent(query)}&num=${num}`;

fetch(url)
  .then(r => r.json())
  .then(data => {
    const results = (data.items ?? []).map(item => ({
      title: item.title,
      snippet: item.snippet,
      url: item.link,
    }));
    console.log(JSON.stringify({ query, results }, null, 2));
  })
  .catch(err => {
    console.error(JSON.stringify({ error: err.message }));
    process.exit(1);
  });
```

### 3.3 exif-reader Skill

**功能**：从图片文件提取 EXIF 元数据（拍摄时间、GPS 坐标、设备信息）。

**SKILL.md 摘要**：
- 调用 `exifr` 库解析图片
- 支持 JPEG / PNG / HEIC
- 输出 JSON：`{ created_at, location: { lat, lng }, device }`

### 3.4 ocr Skill

**功能**：对图片进行 OCR 文字识别，支持 DeepSeek 在线/本地两种模式切换。

**SKILL.md 摘要**：
- 通过 `--provider online|local` 参数切换
- Online：调用 DeepSeek API（`deepseek-vl2`）
- Local：调用本地 Ollama（`deepseek-vl2:7b`）
- 输出：识别出的文字字符串

## 4. 模型策略

### 4.1 模型分工

| 场景 | 模型 | 调用方式 |
|------|------|---------|
| 文本语义提取（摘要、标签、时空） | Gemini 2.5 Pro | Structured Output |
| 图片多模态理解（场景、人物、地点推断） | Gemini 2.5 Pro（vision） | Structured Output |
| 图片 OCR | DeepSeek VL2（在线/本地） | OCR Skill |

### 4.2 DeepSeek OCR 双模式切换

通过 `config.json` 中的 `ocr.provider` 字段切换：

```json
{
  "ocr": {
    "provider": "deepseek-online",
    "deepseek-online": {
      "api_key": "${DEEPSEEK_API_KEY}",
      "model": "deepseek-vl2"
    },
    "deepseek-local": {
      "base_url": "http://localhost:11434",
      "model": "deepseek-vl2:7b"
    }
  }
}
```

### 4.3 Structured Output 规范

所有 LLM 调用通过 Gemini SDK 的原生 `response_schema` 参数约束输出（非 prompt 约束）：

```typescript
const SemanticSchema = z.object({
  summary: z.string(),
  author_inferred: z.string().nullable(),
  tags: z.object({
    keywords: z.array(z.string()),
    entities: z.object({
      persons: z.array(z.string()),
      places:  z.array(z.string()),
      orgs:    z.array(z.string()),
      other:   z.array(z.string()),
    }),
  }),
  spatiotemporal: z.array(z.object({
    period:     z.string(),
    place:      z.string().optional(),
    event:      z.string(),
    confidence: z.number().min(0).max(1),
  })),
  web_search_needed: z.array(z.object({
    entity: z.string(),
    reason: z.string(),     // 为什么需要搜索
    query:  z.string(),     // 建议的搜索词
  })),                      // Agent 据此决定是否调用 web-search
});
```

注意：`web_search_needed` 字段由 LLM 主动标记哪些实体需要网络验证，Agent 据此决定是否触发 `web-search` Skill。

## 5. 元数据结构（FileMetadata）

```typescript
type FileType = 'text_doc' | 'image';

interface FileMetadata {
  // ── 文件属性 ──────────────────────────────────────────
  file_path:     string;
  file_name:     string;
  file_type:     FileType;
  mime_type:     string;
  file_size:     number;
  created_at:    string;          // ISO 8601
  modified_at:   string;          // ISO 8601
  hash:          string;          // SHA-256
  parent_folder: string;
  /** 同一内容曾出现过的路径（改名/移动且内容未变时追加；不触发重新提取） */
  path_history?: Array<{
    file_path:     string;
    file_name:     string;
    parent_folder: string;
    recorded_at:   string;        // ISO 8601，记录检测到迁出时刻
  }>;
  author?:       string;
  location?: {
    lat?:        number;
    lng?:        number;
    place_name?: string;
  };
  device?:       string;          // 仅图片

  // ── 内容语义（Agent + LLM 提取）──────────────────────
  summary:        string;
  tags: {
    keywords: string[];
    entities: {
      persons: string[];
      places:  string[];
      orgs:    string[];
      other:   string[];
    };
  };
  spatiotemporal: Array<{
    period:     string;
    place?:     string;
    event:      string;
    confidence: number;
  }>;
  faces?: Array<{               // 仅图片
    face_id:        string;
    crop_path:      string;
    bbox:           [number, number, number, number];
    matched_person: string | null;
  }>;

  // ── 处理元信息 ────────────────────────────────────────
  extracted_at:      string;
  extractor_version: string;
  agent_used:        string;     // "TextDocAgent" | "ImageAgent"
  model_used:        string;
  extraction_errors: string[];
}
```

### 5.1 路径变更（方案 C）

元数据文件按 **内容 SHA-256** 命名（`{hash}.md`）。当用户**改名或移动**文件但**字节未变**时：

1. 仍命中 hash-skip，**不重新调用** LLM / OCR / 人脸等重流程。
2. 若当前磁盘路径与缓存 frontmatter 中的 `file_path` 不一致（规范化比较）：
   - 将**当前缓存中的** `file_path`、`file_name`、`parent_folder` 作为一条历史压入 `path_history`（带 `recorded_at`）。
   - 用本次 `file-attrs` 结果更新 frontmatter 中的 `file_path`、`file_name`、`parent_folder`。
   - 同步更新 `file_size`、`modified_at`、`mime_type`（与当前文件一致）。
   - **图片**：保留缓存中的 `created_at`（通常为 EXIF 拍摄时间，不因移动而改写）。
   - **文本文档**：同时更新 `created_at` 为当前 OS 元数据（与 `file-attrs` 一致）。

使用 `--force` 时将**忽略** hash-skip，整条管线重新执行，不单独走上述轻量刷新。
